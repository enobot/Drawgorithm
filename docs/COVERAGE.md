# Coverage, capabilities and plan

Status as of 2026-10-27. "Works" means checked in the running app **and** by automated tests. "Partial" means the code runs correctly (tested) and is drawn by the generic renderers, but there is no specialized view and it has not been reviewed visually for every case. One working example does not mean a whole problem family is covered.

The editor offers autocomplete, hovers and parameter hints for JavaScript through Monaco's language service; errors still come from the engine's own parser. The Language menu lists TypeScript, Python, Java and C++ as unavailable until their adapters work (see `src/languages.ts` and `docs/ARCHITECTURE.md`).

The JavaScript adapter does not run your code on the browser's JavaScript engine; it interprets it. Semantics follow JavaScript for the supported subset (including quirks such as `[10, 9, 1].sort()` sorting as strings). Code that needs an unsupported feature is rejected with a message instead of being approximated.

## Staged plan

1. **Stage 1 (this release)**: JavaScript adapter and trace contract; blocks, arrays with pointers and windows, maps, sets, objects, trees, linked lists, call stack; Live Build with previous-valid-state handling; playback; limits; formatting.
2. **Stage 2**: role binding UI (choose a renderer for any variable; mark `dp` as a table, `queue` as a frontier, `slow`/`fast` as pointers); DP table view with dependency highlights from recorded reads; memo-hit labels; LeetCode input conventions (`pos` cycles, adjacency lists, matrices); stack/deque/monotonic labels; Asteroid Collision story view next to the stack.
3. **Stage 3**: graph renderer (node-link from adjacency lists or matrices; visited, frontier, distances, paths), Dijkstra's synchronized graph, distance table and priority queue; heap dual view; union-find forest; trie view.
4. **Stage 4**: backtracking decision tree built from the recorded call tree; divide and conquer; bit view; intervals and prefix sums.
5. **Stage 5**: a second language adapter emitting the same trace contract. Candidate: Python via Pyodide (CPython compiled to WebAssembly) in a worker, traced with `sys.settrace`. Java and C++ need a server-side sandbox (container or microVM with CPU, memory, time and output quotas and no network); a browser worker alone does not isolate native runtimes. Each language gets its own row in the matrix above only after its tests pass.

## Known dependency advisories

- **DOMPurify (critical in `npm audit`, GHSA-p98j-92pf-mc4p, -6688-9rhm-gjv2, -cg2g-xh64-v4q7, -mrv2-3pqr-j5jr, -c6gr-qvv4-5v3f).** Monaco 0.57.0, the latest release, bundles its own copy of DOMPurify 3.4.15 (`monaco-editor/esm/vs/base/browser/dompurify/dompurify.js`); that copy, not the `dompurify` npm package, is what runs. Every advisory needs `IN_PLACE`, `SAFE_FOR_TEMPLATES` or `PARSER_MEDIA_TYPE`. Monaco's `domSanitize.js` uses none of them (it calls `sanitize` with `RETURN_DOM_FRAGMENT` and sanitizing hooks), and in Drawgorithms the HTML it sanitizes is hover documentation from the learner's own code and the TypeScript library, in their own browser. Assessed as not reachable; not fixed, because `npm audit fix --force` would downgrade Monaco and an npm override would not change the bundled copy. Re-check when a Monaco release ships DOMPurify 3.4.17 or later (`npm view monaco-editor@latest dependencies`). Assessed 2026-10-27.

## Product and licensing notes

- Runtime dependencies are MIT licensed (React, Monaco, motion, react-resizable-panels, zustand, acorn, Prettier); fonts (Manrope, IBM Plex Mono, Patrick Hand) are SIL OFL 1.1. Re-check before adding runtimes such as Pyodide (MPL-2.0) or compilers.
- Built-in problem descriptions are original. No problem statements, solutions or tests are scraped or bundled. Drawgorithms is not affiliated with LeetCode.
- Not built yet: accounts, saved sessions on a server, usage quotas, subscriptions, AI explanations. Execution today is free because it runs in the user's browser. Server-side languages and AI would add per-run costs that need metering before any "unlimited" plan. User code should stay out of logs and AI requests unless the user opts in.
